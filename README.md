# Goo — Vue 3 + SVG + Verlet

Клон World of Goo. Ядро, редактор и сущности разделены так, что игра не знает ни одной
конкретной сущности, а сущность не знает ни одной другой.

```bash
npm install
npm run dev      # http://localhost:5173
node test.mjs    # headless-прогон физики и игрового цикла
```

## Два решённых вопроса

**Верле — свой.** ~200 строк в `src/core/verlet.js`. Готовые верле-библиотеки
(verlet-js, PhysicsJS) заброшены и не дают того, что нужно именно здесь: связь как
объект первого класса, по которой ходят шары; правило «эти точки друг друга не видят»;
трение как «гладкость» поверхности. Matter.js и Rapier — импульсные, там пришлось бы
подпирать их костылями ровно в тех местах, где мы хотим управлять поведением. Собственный
солвер занимает столько же, сколько заняли бы обёртки над чужим.

**Папка на сущность.** Пока в каждой лежит один `index.js`, но у сущности впереди спрайты,
звуки, шейдеры, свои утилиты — при загрузке с сервера папка станет единицей поставки.
Подключение — одна строка в `src/entities/index.js`.

## Граница знания

Глобальны только свойства, влияющие на взаимодействие (`core/globals.js`):

| свойство      | смысл                                  |
|---------------|----------------------------------------|
| `mass`        | вес                                     |
| `restitution` | упругость                               |
| `smoothness`  | гладкость: 0 — шершавое, 1 — лёд        |
| `collision`   | `{ world, points }` — с чем сталкивается |
| `attachable`  | можно ли прилепить связь                |
| `suction`     | всасывание                              |

Цвет, «статичный ли шар», лимиты связей, форма трубы — всё это остаётся внутри сущности
и наружу не выходит. Сущность работает с миром только через `EntityContext`:

```js
ctx.addPoint(props) / addLink(a, b) / addCollider(poly)
ctx.query(pred)                      // точки по глобальным свойствам
ctx.nearest(pos, pred, maxDist)
ctx.neighbors(point)                 // граф связей
ctx.pathFrom(point, pred)            // кратчайший путь по связям
ctx.isBlocked(a, b)                  // мешает ли статика отрезку
ctx.applyAccel(point, ax, ay)
ctx.emit(name, payload) / ctx.despawnSelf()
```

У чужой точки видно `x, y, radius` и глобальные свойства — тип и данные чужой сущности
недоступны. Поэтому «дойти до всасывания» формулируется как
`ctx.pathFrom(node, q => q.suction > 0)`: игровой шар ничего не знает о трубе.

## Контракт сущности

```js
defineEntity({
  type, title, icon, z,
  defaults(),                       // данные новой сущности
  spawn(ctx, data) -> rt,           // создать тела, вернуть рантайм
  update(rt, ctx, dt, data),        // кадр
  shapes(data, rt) -> Shape[],      // rt === null → рисуем в редакторе
  pointer: { hit, down, move, up }, // ввод игрока
  editor: {
    create: { start, click, move, shapes, finish },
    bounds, hit, move,                        // нулевой контекст
    handles, moveHandles, deleteHandles, addHandle,  // контекст сущности
    props,                                    // схема инспектора
  },
})
```

Сущности возвращают не Vue-компоненты, а описание фигур (`{k:'circle', x, y, r, fill}`) —
его можно сериализовать и получать с сервера. Рисует их `SvgScene`.

## Редактор

- Кнопки слева строятся из реестра.
- **Нулевой контекст:** рамка — выделить сущности, перетаскивание — двигать,
  клик — войти внутрь, `Del` — удалить.
- **Создание:** клик по кнопке → клики по холсту, `Enter` или повторный клик по кнопке —
  завершить, `Esc` — отменить. Шар завершает создание сам, первым же кликом.
- **Контекст сущности:** рамкой (в любом месте холста) выделяются «ручки», которые вернула
  сама сущность — у рельефа и трубы это вершины, у шара это он сам. `Del` — удалить их;
  если сущность отвечает `false`, мир удаляет её целиком. Двойной клик добавляет вершину.
- `Alt`/средняя кнопка — панорама, колесо — зум. Инспектор справа строится по схеме
  `props()`; глобальные свойства помечены значком «мир».

## Сущности

1. **Рельеф** — статичный полигон, отдаёт миру только гладкость.
2. **Системный шар** — `attachable` всегда `true`; приватно: статичный или физический.
3. **Игровой шар** — `attachable` только когда уже в конструкции. Свободный тянется к
   ближайшей точке с `attachable`, дойдя — ползёт по связям; если из графа связей достижимо
   всасывание, ускоряется и идёт кратчайшим путём, на месте исчезает и шлёт `ball:collected`.
   Игрок перетаскивает шар мышью; при отпускании строится 2–3 связи (`minLinks`/`maxLinks`).
   Друг друга и конструкцию игровые шары не задевают: `collision.points = false`.
4. **Труба** — ломаная, первая точка — устье с `suction`. Найдя рядом точку с `attachable`,
   строит к ней невидимую связь и подтягивает конструкцию.

## Что дальше напрашивается

- разрыв связей при перегрузке и «жир» на стыках;
- сущности с сервера: `import()` вместо строки в `entities/index.js`;
- undo/redo в редакторе (стек снимков `level` уже сериализуем);
- пространственный хэш в `_solvePairs`, если точек станет больше тысячи.
